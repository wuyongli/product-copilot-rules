# Plan Template Router

本 reference 是方案文档结构的入口。`task-workflow` 可以创建最小种子骨架并管理文件生命周期；`product-copilot-rules` 负责方案内容要求和正式方案展开方式。

## 选择模板

| 当前状态 | 读取内容 | 产出 |
| --- | --- | --- |
| 首轮分析、仍有关键不确定项 | [seed-plan.md](seed-plan.md) | 种子版 `plan.md` |
| 方向、范围、系统落点已稳定 | [formal-plan.md](formal-plan.md) | 正式版 `plan.md` |
| 涉及表、字段、索引或历史数据 | 在所选模板基础上读取 [data-change-plan.md](data-change-plan.md) | 数据变更与上线章节 |

不要为一次任务同时加载全部模板。没有数据变化时，不读取也不生成数据变更模板。

## 正式方案的章节规则

- 固定核心：目标与成功标准、当前系统现状、范围与取舍、推荐方案、验收、风险与待确认项。
- 条件章节：角色与业务流程、非功能要求、依赖地图、开发方案、数据、权限、灰度、监控、迁移、上线与回滚。
- 条件章节不适用时直接省略，不保留空标题或“无”占位。
- 同义内容只保留一个落点；更新旧结论时直接归并重写，不在文末追加另一版口径。

## 与 `task-workflow` 配合

- 使用 `task-workflow` 已创建的 `plan.md` 路径，不创建平行主方案。
- 现有种子骨架是内容载体，不要求与本目录模板逐字一致；优先归并同义章节。
- 当方案需要正式展开或补充数据变更时，按本目录模板补齐适用内容。
- `decision-log.md` 保存候选方案、被否路径和口径变化过程；稳定结论与核心原因回写 `plan.md`。
- `progress.md` 只记录执行、验证、发布和阻塞，不承载产品方案正文。
- 复杂任务可以拆 `*-plan.md` 或 `appendix-*.md`，但主 `plan.md` 必须保留导航和当前有效结论。
